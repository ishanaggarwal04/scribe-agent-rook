## How rook runs the script

rook runs the script once per phase, on its own Node (>=22):

    <rook's own node>  scripts/local.mjs  <phase>

Every call also gets the always-on env — `ROOK_HOOK`, `ROOK_WORKSPACE`,
`ROOK_PROJECT`, `ROOK_AGENT`. The table shows what each phase adds, what it
reaches, and what it must return.

| Phase | Mode | Reaches | Invoked as | Input rook sends | Returns (stdout JSON) |
|-------|------|---------|------------|------------------|-----------------------|
| prepare | N/A | — | — | — | — |
| open | cli | python[3] -m incident_scribe open | `local.mjs open` | env `ROOK_STATE_DIR`, `ROOK_SCENARIO_ID` | `conversation` |
| execute | cli | python[3] -m incident_scribe execute | `local.mjs execute` | env `ROOK_CONVERSATION`, `ROOK_TURN`; **the goal on stdin** | `agent_reply`, `conversation`, `calls`, `usage` |
| close | N/A | — | — | — | — |
| collect | N/A | — | — | — | — |

A non-zero exit means the phase failed, and stderr says why.
